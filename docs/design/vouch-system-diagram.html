Vouch is a delivery system, not just a verifier.

The adoption correction

Successful initialization and strong internals produce an integrated project—not an adopted one. Adoption requires real governed delivery, demonstrated value, a later independent change, and sustained use.

03

Brownfield-first, with a real greenfield fast lane.

The paths differ in how they establish trustworthy scope. They converge on the same hard-gated pilot, scorecard, and sustained-use standard.

Greenfield target

Governance before product behavior

Repository age is irrelevant. The path is greenfield only when product behavior starts after governance is established.

  1. Set governance root, roles, tier, delivery authority, and scope manifest.
  2. Verify minimal bootstrap infrastructure under a separate bootstrap claim.
  3. Keep disposable discovery in an explicit exploration area.
  4. Establish the verified baseline.
  5. Deliver the first real behavior through the normal governed path.
Brownfield target

Bound, characterize, pilot, ratchet

Pre-Vouch behavior remains visibly characterized rather than acquiring retroactive causal assurance.

  1. Bound the legacy baseline and visible ungoverned scope.
  2. Generate a budget-limited candidate map.
  3. Confirm meaning, exclusions, dependencies, and authorities.
  4. Characterize existing behavior without built-under-Vouch claims.
  5. Run one hard-gated pilot, then expand through an explicit ratchet.
Prototype rule: retained pre-governance behavior becomes brownfield even in a new repository.
Proof rule: a pilot is proven after one real hard-gated change meets predeclared criteria.
Adoption rule: adopted requires a later governed change plus the declared observation window.
04

Incremental verification is exclusion by proof.

Large projects rerun the affected closure. Unchanged scopes are reused only when every bound condition remains identical.

Soundness invariant
Incremental composition must never pass when full verification of the same supported state and change would fail.

Pure versus effectful code influences dependency contracts and volatility—not ownership. An unchanged mechanically bound contract can stop downstream propagation; an opaque dependency cannot.

05

Three modes preserve speed without hiding assurance depth.

A release can make a complete project claim through sound composition without pretending every active scope or every historical event was re-executed.

Ordinary target

Incremental composition

Freshly verify the affected closure, reuse only exact valid capsules, and check global composition.

  • Ordinary changes
  • Eligible release rosters
  • Volatile scopes always rerun
Current-scope depth

Full verification

Execute every active governed scope and every current-state global obligation without change exclusion.

  • Missing baseline
  • Global invalidator
  • Policy cadence or force-full
History depth

Historical scrub

Replay and validate authoritative events and evidence from genesis to the current head.

  • Recovery or corruption
  • Incompatible upgrade
  • History audit or longer cadence

Branches and merges

Use the exact common verified ancestor, combine manifests, evaluate the merged tree, and never union green outcomes blindly.

Parallel plans and retries

Receipts append. Same-plan passes can survive a partial run; any relevant input change creates a new plan. Retries are explicit and bounded.

Bootstrap and migration

Greenfield establishes a baseline before governed behavior. Existing mk2 stays full-only until human scope confirmation, full verification, and scrub.

07

Local operation is an architectural constraint.

Adoption support and fleet visibility do not require telemetry, a daemon, or a central control plane.

∅

No telemetry of any kind

Vouch never sends project or adoption data—not anonymously, not by default, and not through an opt-in telemetry channel. The adopter's chosen forge remains an external delivery environment, not a Vouch data service.

09

The strongest system is explicit about what it cannot know.

Repository-local integrity supports bounded claims. It does not manufacture independent authority or organizational truth.

External

Test adequacy and runner honesty

A recorded exit status does not prove the selected tests were adequate or the runner was honest.

External

Identity, independence, and intent

Roles and actor values are claims unless authenticated and governed by an external authority.

External

Chronology and value

Wall-clock values alone do not prove chronology; scorecard meaning and exception reasons remain accountable human judgments.

Adopter-owned

Forge and deployment protection

The real workflow must protect the dependency from project tests and Vouch composition to release authority.

Target constraint

Baseline-relative reuse

Capsules and checkpoints are trustworthy only relative to their exact baseline, inputs, verifier, and hard-gated revision.

Trust root

Coordinated authority compromise

Vouch cannot defeat an actor controlling the repository, pinned executable, workflow policy, runner, and credentials together.
