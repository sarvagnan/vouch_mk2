Vouch 2 — Rebuild Architecture

A typed policy engine with one authoritative snapshot, immutable content-addressed artifacts, pure projections, and thin adapters. Synthesized from dual independent reviews of the Vouch 0.6 defect history — 70 recorded defects, 31 behavioral hardening commits.

0Why this shape — defect class → structural mechanism

Each mechanism below exists because a class of recorded defects demanded it. The goal is that each class becomes unrepresentable, not re-checked: an unbound claim fails to parse, an ungated transition has no code path, an unevaluated obligation fails the whole run.

Defect class (Vouch 0.6 history) Mechanism in Vouch 2 Where
Vacuous / self-certifying checks 10 defects — largest class Obligation registry: every registered check must resolve to an evaluator that ran, or the run fails. An authority never supplies its own discriminator — coverage claims need independent witnesses. §3
Missing bindings between artifacts tied #1 commit root cause Content-addressed references are typed schema fields validated at decode. An unbound claim is unparseable, not a review finding. §1
Fail-open validation 6 defects · 6 commits Gate check and state transition are one code path inside pure decide(); only PASS composes to PASS. §2 step 4, §3
Duplicated authority / policy drift 7 defects · 3 commits One declarative Policy IR; runtime tables, schemas, formal model input, and docs are generated views that cannot disagree. §1
Coupled writes / atomicity 5 defects · 3 commits One mutable file, compare-and-swap on a monotonic revision; immutable objects written first. No multi-file transaction exists to recover. §2 steps 5–6

1Entity & authority diagram

Five layers, each with exactly one home for every fact. Every sha256 chip is a content-address reference validated by the typed decoder — the anti-“missing binding” measure.

Human authority prose · reviewed · non-mechanical

  • Method rationale — the “why” the IR cannot express.
  • Threat model — the three explicit levels (§4).
  • Claim boundary — what is mechanically provable vs. permanently NOT_CHECKED.
▼governs — humans review every IR change against it

Policy IR one declarative definition · versioned · digested

  • Lifecycle states & the transition table — defined once, copied nowhere.
  • Claim taxonomy — completion / negative evaluation / protective closure.
  • Applicability matrix · assurance-tier requirements.
  • Obligation registry — the closed list of check IDs that must run (§3).
▼generates — every mechanical view is derived; none is hand-maintained

Typed runtime tables

Consumed by the domain core. The engine cannot disagree with the IR — it is the IR, compiled.

JSON Schema exports

Interop only, never enforcement. Strict typed decoders in the core are the enforcement layer; no miniature validator exists to drift.

Formal model input

The emitted transition relation — the model checks the same relation the runtime executes, so model↔CLI conformance is an identity, not a correspondence.

Invariants & mutation witnesses independently authored

Deliberately not generated — generation would reproduce the IR’s own mistakes. Each counted invariant carries a private raw mutation witness; witnesses are never borrowed (D040/D042/D043 discipline).

Formal checker → certificate

Binds IR model witnesses plus per-invariant verdicts. Reproducible, content-addressed; unknown is never a pass.

▼tables compiled into

Typed domain core one library · pure · no I/O

  • Closed types: Unit · Release · Deviation · Evidence · Command · Event.
  • decide(Snapshot, Command) → Events | Violations — the only place lifecycle rules exist.
  • Stable check IDs; structured verdicts (§3). No command handler implements policy.
  • Strict decoders at every ingress: unknown field = error, coercion = error.
▼reads and writes exactly one aggregate

Authoritative state .vouch/ · single mutable aggregate + immutable objects

  • state.json — monotonic revision (CAS), policy sha256, units[] → pack sha256, releases[] → bundle sha256 criteria sha256, deviations[] bound to NAME@VERSION, evidence heads sha256 (refs into the chain, like git).
  • objects/sha256/… — immutable, content-addressed: acceptance packs, contracts, evidence events, release bundles, certificates, closure witnesses.
  • vouch.lock — the single vendored artifact (a typed-Python zipapp, one digest). Replaces the entire ownership-manifest / collision subsystem; hermetic CI preserved.
  • local.json — explicitly non-authoritative; never read by a gate.
▼projected by pure functions — never inside the transaction

Projections derived · regenerable · byte-comparable

  • System map — canonical JSON first; HTML presentation added only after the semantic projection is stable.
  • Next actions — derived from the dependency graph; binding from day one, never advisory.
  • Status facts and agent context (kernel → AGENTS.md / CLAUDE.md suggestions).
  • A stale projection is a freshness failure in CI — never a half-committed state transition.
▼exposed through

Transports thin · zero policy

CLI · CI command · MCP (read/verify-only, permanently) · edit hooks (warn-only, honestly). Each parses input, calls the core, renders the structured result — none infers outcomes from text, none re-implements a rule.

2Mutation flow — the only write path

Init, migration import, freeze, status changes, and release operations are all modes of this one path — there is no bypass to drift. The crash story is trivial by construction: before the swap, garbage; after it, done.

1
Open the project through a capability root All paths become validated relative types under one handle — no string re-interpretation, no scattered resolve() calls, descriptor-relative operations.
Anti path-handling class. One confinement implementation instead of the ~11 clusters in Vouch 0.6.
│
2
Acquire the project lock One lock implementation, one ordering — not a general ledger lock plus a private evidence-anchoring flock.
│
3
Read state.json once → strict decode → Snapshot Unknown field = error. The snapshot is never re-read mid-operation, so a swapped second read can never ride on the first read’s validation.
Anti-TOCTOU (logical). Makes the single-snapshot anchor repair an API property, not a local fix.
│
4
decide(Snapshot, Command) — pure, no I/O Gate evaluation and the transition are one code path: “published without unit-done” is unrepresentable. Violations render as structured verdicts and exit non-zero.
Anti fail-open. The class behind D046, ungated CI, and the set-status published bypass.
│
5
Write new immutable objects first Packs, evidence events, bundles, certificates land in objects/sha256/… before any authority changes.
Crash here → unreferenced objects only. Harmless; collectable later.
│
6
Atomically replace state.json — CAS on expected revision One file swap carries the entire transition. There is no ledger + map two-file transaction, so the journal and its recovery protocol have no reason to exist.
Crash after → authoritative state is complete. Nothing to recover.
│
7
Release the lock State is durable; readers see either the old or the new revision, never a blend.
│
8
Separately: vouch generate refreshes projections Map, next actions, status facts regenerate from the new snapshot. CI regenerates into memory and byte-compares — staleness is a visible freshness FAIL, never corruption.
Anti stale-artifact class. D052 (stale map after publication) cannot occur — the map was never a transaction participant.

3Verification flow — how a check run composes

Aimed squarely at the largest defect class: checks that pass without proving anything. A check that silently didn’t run fails the run; a claimed coverage needs a witness the claimant didn’t author.

vouch check --ci → load one Snapshot

Single read, strict decode. Anchors and evidence heads validate against this same snapshot — no second read to swap underneath.

▼

Obligation registry from the Policy IR

The closed list of every check ID that must run for this project’s tier. Every registered obligation must resolve to an evaluator that actually executed — otherwise the entire run fails. An obligation that was never registered cannot pass by omission: registry completeness is itself a checked projection of the IR.

▼dispatches

Evaluators over Snapshot + objects

Each returns a structured verdict bound to its evidence:

PASS — evidence sha256 FAIL — names the violated rule NOT_CHECKED — honest, propagates visibly NOT_APPLICABLE — must cite the IR applicability rule
▼

Composition rule

  • Only PASS composes to PASS. SKIP does not exist as an outcome.
  • NOT_CHECKED propagates to the top-level result — organizational claims stay honest: neither failures nor manufactured passes.
  • NOT_APPLICABLE is only legal with a citation into the IR’s applicability matrix — applicability can never be self-declared by the artifact under test.
  • An authority never supplies its own discriminator — any coverage or distinctness claim requires an independent witness.
▼

One structured result

Machine-readable verdict tree → a single presentation layer maps it to text and exit code. CLI, MCP, hooks, and CI consume the same structure — no transport ever parses output text.

Closure harness dev-repo CI only · not shipped

For every fixed defect: materialize the pre-fix tree — the witness must FAIL there with the exact defect ID and PASS at HEAD, plus a positive twin. This discrimination is the standing definition of “this check checks something” — the antidote to the vacuity class, kept small and outside the product runtime.

4Threat levels — the honest boundary

Written first, before any code: every check is born declaring its scope, instead of extracting the boundary through thirty defects.

Level 1 — Accidental inconsistency

Vouch prevents it. Snapshot consistency, CAS commits, typed decoding, digest bindings, and the obligation registry make ordinary mistakes unrepresentable.

Level 2 — Adversarial repository content

Vouch parses and validates safely. Capability-rooted paths, symlink refusal, strict decoders, content-addressed retrieval. Hostile-concurrent-writer TOCTOU (D070) is narrowed to the platform limit and documented, not silently absorbed.

Level 3 — Hostile rewrite of tool, lock & branch rules

Outside Vouch — by declaration. An actor who can rewrite vouch.lock, the workflow, and branch protection defeats any repository-local mechanism. Addressed by review, signatures, and forge governance; never claimed otherwise.
