# workflow-refresh@1 acceptance pack

**Owner:** Claude (acceptance owner). **Implementer:** Sol, who may not edit this file,
`tests/test_workflow_refresh.py` or `packs/workflow-refresh-1.effects.json`.
**Decision:** D-55 (`vouch_mk2-bd4.4.26`). **Seams (D-44):** the CLI in process (`init`,
`check --ci`, `refresh-workflow`) on scratch projects; the workflow bytes `init` writes in a fresh
project as the oracle for the generated workflow; `Store.init` for a store `init` did not write;
mk2's own checkout read-only; the text of `docs/*.md`.
**Effects:** declared in `packs/workflow-refresh-1.effects.json`.

## Promise

**The row.** `check` gains `check.workflow-current`. Applicability is decided by the store first:
it is `NOT-APPLICABLE` when the store root given to `check` holds no `config.json` (a store `init`
did not write, such as mk2's own or the README gates' scratch store), whatever the project; it is
also `NOT-APPLICABLE` when no project root is given, so existing checks without `--project` keep
their exit code. Otherwise it is `PASS` only when `<project>/.github/workflows/vouch.yml` is a
regular file reached without any symlink (not at `.github`, `.github/workflows` or the file) whose
bytes equal, byte for byte with no newline conversion, the workflow the running Vouch generates
(the bytes `init` writes). Anything else (a missing file, a symlink at any of those three paths,
a directory, any byte difference) is `FAIL` at every tier, with a detail that names
`refresh-workflow`. A `FAIL` makes `check --ci` exit 1, as any failing row does. The row reads only
that file and `config.json`'s presence in the store root.

**Refresh.** `vouch-mk2 refresh-workflow --project PATH` writes the running Vouch's generated
workflow to `<project>/.github/workflows/vouch.yml` (mode `0644`), creating the directories if
they are missing, through a temporary file in the same directory and an atomic rename, so no
temporary file is left and a file hard-linked elsewhere is replaced, never written through. It exits 0 whether it rewrote the file or found it current; a current file
is left byte-for-byte as it was. It writes nothing else: the store and every other file are
unchanged. It refuses, with exit 2, nothing written and a message naming the cause:
- a project without `.vouch/config.json` (the message names `config.json`), and
- a symlink at `.github`, `.github/workflows` or `vouch.yml` (the message names a symlink), with
  nothing written through it or anywhere in the project, even when the symlinked file already
  holds the generated bytes.

**Docs.** `docs/quickstart.md` documents re-pinning the lock, including the sentence pinned in R7;
`docs/claim-boundary.md` states the row; `docs/commands.md` is regenerated with the new command.

## Requirements

Expected RED reasons, before the change: `check` has no `check.workflow-current` row, so every
check test fails finding exactly one such row; `refresh-workflow` is not a command, so argparse
exits 2 before anything else (R5's `_must` fails; R6's messages do not name `config.json` or a
symlink); the docs lack the text. No guards (R4's bare-store and store-first cases also fail on
the missing row).

- **R1 — A fresh adoption passes.** `test_a_freshly_adopted_project_passes` (lightweight,
  standard, high): `PASS`.
- **R2 — Any difference fails.** `test_a_changed_workflow_fails_at_every_tier` (appended, edited,
  emptied, CRLF line endings × three tiers): `FAIL` naming `refresh-workflow`; `check --ci` exits 1.
- **R3 — Missing or irregular.** `test_a_missing_or_irregular_workflow_fails` (missing; a symlink
  to identical bytes; a directory; identical bytes behind a symlinked `workflows` or `.github`
  directory): `FAIL` naming `refresh-workflow`, exit 1.
- **R4 — Applicability.** `test_without_a_project_root_the_row_is_not_applicable`: an adopted
  store with a drifted workflow, checked without `--project`: `NOT-APPLICABLE`.
  `test_a_bare_store_checked_alone_is_not_applicable_and_passes`: the README gates' shape
  (`Store.init`, `check --ci --root` only): `NOT-APPLICABLE` and exit 0.
  `test_the_store_decides_applicability_not_the_project`: a bare store with an adopted project
  is `NOT-APPLICABLE`; an adopted store with a project directory that has no workflow is `FAIL`.
  `test_a_store_that_init_did_not_write_is_not_applicable`: `NOT-APPLICABLE` even with a
  `vouch.yml` present. `test_mk2s_own_store_is_not_applicable`: mk2's checkout, `NOT-APPLICABLE`.
- **R5 — Refresh.** `test_refresh_restores_the_generated_workflow` (an edited file; a missing
  file; a file hard-linked to one outside the project, which keeps its bytes; no `.github`
  directory at all): exit 0, bytes equal to `init`'s, a regular file with mode `0644`, the
  project's other workflow and the store unchanged, no other file left in the directory, and the
  row passes.
  `test_refresh_of_a_current_workflow_changes_nothing`: every project file unchanged.
- **R6 — Refusals.** `test_refresh_refuses_a_project_init_did_not_adopt`: exit 2, names
  `config.json`, nothing created. `test_refresh_refuses_a_symlinked_path` (the file, the file
  holding the generated bytes, the `workflows` directory, the `.github` directory): exit 2, names a
  symlink, nothing written outside or in the project.
- **R7 — Docs.** `test_docs_state_the_row_and_the_re_pin_step`: `docs/quickstart.md` contains,
  whitespace normalised, "After you re-pin `vouch.lock`, run `python3 vouch.lock refresh-workflow
  --project .`"; `docs/claim-boundary.md` contains "For a store `init` wrote, checked with
  `--project`, `check.workflow-current` fails when `.github/workflows/vouch.yml` differs from the
  workflow the running Vouch generates.";
  `docs/commands.md` names `refresh-workflow`.

## Ground rules

- **Code.** The comparison uses the same generated-workflow source `init` uses; `init`'s output
  does not change. The row is a new artifact-check obligation in the IR with the applicability
  above, implemented beside the other project-root checks; the refresh reuses `init`'s
  owned-path preflight and an atomic write. No change to `decide`, any gate, the state or event
  formats, formal universes, or the generated workflow itself.
- **Fallout.** Tests that pin the IR's artifact-check set (for example `tests/test_mk2_ir.py`) or
  the command list change with this unit; if such a test is bound to another unit's frozen pack,
  Sol lists it in the DONE file and does not edit it, and the owner adapts and rebinds; otherwise
  Sol updates it and lists it.
- **Docs.** The re-pin section in `docs/quickstart.md`: replace `vouch.lock`, update the digest in
  `.vouch/config.json`, `python3 vouch.lock upgrade --root .vouch`, `python3 vouch.lock
  refresh-workflow --project .`, `python3 vouch.lock check --ci --root .vouch --project .`, then
  commit. Any new `sh` block there must run under `tests/test_operator_docs.py`; otherwise use a
  non-executed fence. The quickstart's blanket statement that commands take `--root` is qualified
  for `refresh-workflow`, which takes `--project`. The R7 sentence in `docs/claim-boundary.md` beside the projection-freshness
  rows; `docs/errors.md` if refusals have codes; `docs/commands.md` regenerated; keep every pinned
  phrase.
- **Out of scope.** Writing `vouch.lock` or `config.json` (release-upgrade@1,
  `vouch_mk2-b6g.14.3`); the project's own caller job; comparing anything but `vouch.yml`.

## Limits (convergence bound, set before review)

A review blocks only on: a row verdict or exit code that differs from the Promise for a project
`init` wrote or a hand edit of `vouch.yml`; a refresh that writes anything but `vouch.yml`, writes
through a symlink, leaves a temporary file, or writes bytes other than `init`'s; a refusal that
writes; a change to `init`'s output, the generated workflow, `decide`, a gate or a format; a false
statement in a changed doc; or a pinned phrase removed. Wording beyond what the tests pin is a
note.
