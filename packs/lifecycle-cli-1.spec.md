# Acceptance pack — unit `lifecycle-cli@1` (pack/1)

**Owner:** acceptance owner (Fable, on the user's behalf). **Implementer:** Codex. The
implementer may NOT edit this file or `tests/test_lifecycle_cli.py`. A finding that this pack
is wrong is a DEVIATION, adjudicated by the owner. Bead: vouch_mk2-bd4.1 (epic bd4).

## Intent

mk2 has a complete typed lifecycle (27 commands in `vouch_mk2.core.commands`, each named by
an `ir_command` that matches an `ir.mk2.CMD_*` constant) and no way to drive it without
writing Python: both self-hosted units were operated by inline scripts, evidence via
`scripts/record_pytest_evidence.py`. This unit gives every command a `vouch-mk2` verb of the
SAME name, generated from the command set so it cannot drift.

## Requirements (each bound to a test)

R1 `vouch_mk2.cli.LIFECYCLE_VERBS` — a mapping verb-name → handler, generated by reflecting
   the `Command` dataclasses in `vouch_mk2.core.commands` (all classes with `ir_command`).
   Set equality with the core command set AND with `ir.mk2.CMD_*` is tested.
   → `test_every_ir_lifecycle_command_is_a_cli_verb_and_vice_versa`
R2 Every verb takes `--root ROOT` (required) and `--json`; `--help` exits 0 and mentions
   `--root`. → `test_every_verb_parses_help`
R3 Arguments are reflected from the command's fields: `str` → `--field`; `tuple[str, ...]` →
   repeatable `--field` (deduplicated, order kept); enums (`Tier`, `AnchorMode`,
   `DeviationType`, `EvidenceKind`) → `choices` of wire values; `UnitRef` → `NAME@VERSION`
   (`@` is forbidden inside names/versions, so the split is injective) with a usage error
   (exit 2, message naming `NAME@VERSION`) on a bad ref; `LaunchCriteria` →
   `--launch-criteria` (repeatable) + `--verification-window`. Field names use kebab-case.
   → `test_enum_fields_are_argparse_choices`, `test_unit_ref_is_name_at_version_and_bad_refs_are_usage_errors`,
     `test_specify_accepts_repeated_depends_on`
R4 Accepted: `decide` → `apply` → `Store.commit`; print one line naming the subject
   (`NAME@VERSION` for units) and its new status / the recorded fact; exit 0. `--json` prints
   `{"accepted": true, "revision": N, "events": [{"event": "<kebab-case event name>", ...}]}`.
   → `test_specify_creates_the_unit_and_reports_the_new_status`, `test_json_output_lists_events_and_new_revision`
R5 Refused: nothing is committed (revision unchanged; no temp files); stderr lists each
   violation as `<code>: <detail>`; exit 2. `--json` prints
   `{"accepted": false, "violations": [{"code", "detail"}]}` on stdout, exit 2.
   → `test_refusal_prints_violation_codes_exits_2_and_leaves_store_untouched`, `test_refusal_json_carries_codes`
R6 `record-evidence --root R --unit NAME@VERSION --kind red|green|refactor -- <argv...>` RUNS
   argv (inherit stdio; no shell), derives outcome from the exit status (0 → tests-passed,
   else tests-failed), sequence/parent from the store's current head, `command_line` = the
   exact argv joined; records through `vouch_mk2.verify.record_evidence` (so kind/outcome
   coherence is enforced by decide — an incoherent kind is a refusal, exit 2, nothing
   recorded, stderr says "coherence"). There is NO `--outcome`, `--sequence`, `--parent`
   or `--recorded-at` flag. Prints `[evidence] recorded <kind> #<seq> for NAME@VERSION: <digest16>`.
   → `test_record_evidence_runs_the_command_and_records_the_real_outcome`,
     `test_record_evidence_refuses_an_incoherent_kind_and_records_nothing`,
     `test_record_evidence_has_no_typed_outcome_flag` (guard)
R7 `record-formal-certificate --root R` runs the formal checker and records the passing
   certificate (same as `formal --root R --record`, which stays); NO `--certificate-digest`.
   → `test_record_formal_certificate_verb_runs_the_checker_not_a_typed_digest` (guard)
R8 `next` actions name CLI verbs (`NextAction.command ∈ LIFECYCLE_VERBS`); the `next` output
   shows the invocation (`vouch-mk2 <verb> --root … --name …`).
   → `test_next_action_commands_are_cli_verbs`
R9 The verbs ship in the lock (`python3 vouch.lock specify --help` exits 0 with empty PATH).
   → `test_lock_exposes_the_lifecycle_verbs`
R10 `scripts/record_pytest_evidence.py` is deleted; CI, docs, README and
   `scripts/walkthrough.py` reference the verb instead. → `test_record_pytest_evidence_script_is_absorbed_by_the_verb`

## Ground rules

- Read-only stores (MCP pinned root) gain no mutation path — the verbs are CLI only.
- The store is opened once per verb, held under the lock across decide/apply/commit.
- No new I/O in the pure layers (import-linter contracts kept); Pyrefly strict clean; every
  pre-existing test green; README test count re-pinned by the owner.
- Docs: `docs/claim-boundary.md`/README name the verbs; `docs/quickstart.md` is a SEPARATE
  unit (bd4.3) — do not write it here.
- Existing verbs (`check formal generate next status emit-context build-lock self-check init
  mcp hook migrate`) unchanged.
